# eTeleprompter — Technical Plan

Authoritative spec: `team/SPEC.md`. Scaffold is committed on `main` and **builds
clean for both destinations** (iOS Simulator + macOS). Engineers start from it.

## 1. Architecture overview

One SwiftUI multiplatform target `eTeleprompter` (iPadOS 17 / macOS 14, native, no
Catalyst), MVVM, SwiftData. Project is generated by XcodeGen (`project.yml`) but
uses **synchronized folders**: add/delete Swift files under `eTeleprompter/` or
`eTeleprompterTests/` and Xcode picks them up — **never edit the pbxproj, never
regenerate** unless build settings change (tech lead only).

### Module layout (all paths relative to repo root)
```
eTeleprompter/
  App/          eTeleprompterApp.swift (entry, .modelContainer, WP5 adds .commands)
                RootView.swift (NavigationSplitView shell + prompter overlay)
                AppState.swift (@Observable; prompterScript: Script?)
                SidebarItem.swift (enum: .allScripts | .folder(Folder))
  Models/       Script.swift, Folder.swift (SwiftData @Model)
  Engine/       PrompterEngine.swift, PrompterClock.swift (+ WP4 files)
  Features/
    Library/    SidebarView.swift, ScriptListView.swift (+ WP2 files)
    Editor/     EditorView.swift (+ WP3 files)
    Prompter/   PrompterView.swift (+ WP5 files)
  Settings/     ReadingSettings.swift (+ WP4 files)
eTeleprompterTests/ PrompterEngineTests.swift (+ WP4 tests)
```

### MVVM conventions
- Views are dumb; SwiftData `@Query` + `@Bindable` model objects cover most of
  Library/Editor — a separate VM class is only warranted where there is real
  logic (duplicate-naming, engine). Name VMs `<Feature>ViewModel`, mark
  `@Observable @MainActor`, keep them in the feature folder.
- Non-trivial pure logic (copy-name generation, `Xm Ys` formatting, search
  filtering) goes in plain testable functions/types, not in view bodies.

### PrompterEngine stays UI-independent
- `Engine/` imports **Foundation + Observation only** — never SwiftUI/UIKit/
  AppKit. The engine is an `@Observable` class exposing `offset: Double`
  (points from top), `speed: Double`, and a state machine
  (`stopped | playing | paused`), with `play/pause/stop`, `contentHeight` input,
  and auto-stop at end.
- It is driven by the `PrompterClock` protocol (`start(tick:)/stop()`).
  Production clock (`Features/Prompter/DisplayLinkClock.swift`, WP5-owned file)
  wraps `CADisplayLink` (iOS) / `NSScreen.displayLink(target:selector:)` or
  `CVDisplayLink` (macOS 14). Tests drive the engine with a manual clock
  advancing fixed deltas — ramping and clamping are asserted without any UI.
- The view renders text inside a `ScrollView`-free container: full text laid
  out in a `Text` inside a clipped frame, translated by
  `.offset(y: -engine.offset)`. No `ScrollViewReader` animation — offset is
  driven per-frame by the engine (this is what makes 60 FPS on 10k words work;
  avoid re-laying-out text per frame — layout once, translate only).

## 2. Key technical decisions

- **SwiftData container:** `.modelContainer(for: [Script.self, Folder.self])`
  on the WindowGroup (already in scaffold). Default store location; no
  CloudKit. Auto-save is SwiftData's autosave + explicit
  `modifiedDate = .now` on every title/content/folder mutation.
  `wordCount`/`estimatedReadingTime` are computed properties (never stored).
  Folder→Script delete rule is `.nullify` (already modeled) — SPEC item 5.
- **Settings persistence:** `ReadingSettings` is one `Codable` struct (fonts,
  size, spacing, margins, colors as palette indices, mirror/flip/rotation,
  speed). Persist as JSON `Data` in a single `@AppStorage("readingSettings")`
  key via a small `@Observable SettingsStore` (WP4). Global, not per-script
  (SPEC F3). Colors are stored as palette *indices*, not Color values.
- **Keyboard handling:** in PrompterView attach a hidden focused view with
  `.onKeyPress(.space/.upArrow/.downArrow/.escape)` (iOS 17.4+/macOS 14.4 —
  acceptable; if baseline must be exactly 17.0 use `.keyboardShortcut` on
  hidden buttons as fallback, decide in WP5). macOS additionally gets real
  menu items via `.commands` in `eTeleprompterApp.swift` (Transport menu: Play/
  Pause Space, Speed +10 ↑, Speed −10 ↓, Exit Esc) targeting the engine
  through `@FocusedValue` or AppState.
- **Full-screen presentation:** `fullScreenCover` does not exist on macOS, so
  RootView overlays `PrompterView` (already wired via
  `AppState.prompterScript`). Same code path on both platforms.
- **Mirror transforms:** applied to the **reading container only** — the view
  that clips/offsets the text: `.scaleEffect(x: mirrorH ? -1 : 1,
  y: flipV ? -1 : 1)` then `.rotationEffect(.degrees(rotation))`. The control
  overlay and settings sheet are siblings in the ZStack *outside* that
  container, so they are never transformed (SPEC item 8). Transforms are pure
  render effects → toggling never interrupts the engine.
- **Interface freeze:** `App/*` files and the stub view signatures
  (`SidebarView(selection:)`, `ScriptListView(sidebarItem:selection:)`,
  `EditorView(script:)`, `PrompterView(script:)`) are shared contracts.
  Changing them requires tech-lead sign-off; parallel packages must not edit
  files outside their ownership list below.

## 3. Work packages

### WP1 — Scaffold [sequential — DONE, on main]
Project generation, models, container, nav shell, stubs, test target.
Serves acceptance items 1, 2 (both builds verified).

### WP2 — Library [parallel]
**Owns:** `eTeleprompter/Features/Library/*` (edit the two stubs; add e.g.
`FolderRowView.swift`, `ScriptRowView.swift`, `MoveToFolderMenu.swift`,
`DuplicateNamer.swift` as needed).
**Depends on:** WP1 only.
**Scope:** sidebar folders (`@Query`), + New Folder, inline rename, delete with
confirmation (scripts survive — rely on `.nullify`); script list filtered by
`SidebarItem`, sorted `modifiedDate` desc; rows show title, modified date,
word count, reading time; `.searchable` case-insensitive over title+content;
"+" creates `Untitled` and selects it (binding opens editor); context menu +
swipe: Duplicate (`<Title> copy`, `copy 2`, …), Move to Folder, Delete with
confirmation.
**Done when:** acceptance 3 (create+persist), 4 (duplicate half), 5 (folder
delete) pass in iPad Simulator and on macOS.

### WP3 — Editor [parallel]
**Owns:** `eTeleprompter/Features/Editor/*` (+ e.g. `ReadingTimeFormatter.swift`
inside that folder).
**Depends on:** WP1 only.
**Scope:** title `TextField` + full-height plain `TextEditor` bound to
`@Bindable script`; every keystroke updates `modifiedDate` (SwiftData
autosaves — no Save button); toolbar: word count, reading time (`2m 0s` /
`45s` format), prominent Start Prompter button → `appState.prompterScript =
script` (stub PrompterView appears until WP5 lands — that's fine).
**Done when:** acceptance 3 (typed content persists) and 4 (300 words → `300`,
`2m 0s`) pass.

### WP4 — Engine + Settings model [parallel]
**Owns:** `eTeleprompter/Engine/*`, `eTeleprompter/Settings/*` (add
`SettingsStore.swift`, `PresetPalette.swift`), `eTeleprompterTests/*`.
No UI — do not touch Features/ or App/.
**Depends on:** WP1 only.
**Scope:** PrompterEngine state machine (stopped/playing/paused; play, pause
resume-in-place, stop→offset 0; auto-stop when `offset ≥ contentHeight`);
speed clamped 10–300, default 60, step 10; **0.3 s linear ramp** of actual
rate on every speed change and play/pause (displayed target changes
immediately — expose both `speed` target and internal ramped rate);
`PrompterClock` production-free tests with manual clock. Full
`ReadingSettings` fields + defaults (SF Pro 48 pt, 1.4, 10 %, white-on-black)
+ `SettingsStore` (@AppStorage JSON) + 8-swatch palette definition.
**Done when:** unit tests cover ramp timing, clamping, transport transitions,
auto-stop; settings round-trip through encode/decode; both destinations still
build; `xcodebuild test` (macOS destination) green. Serves acceptance 6, 7, 8
foundations.

### WP5 — Prompter reading view [sequential — after WP2, WP3, WP4]
**Owns:** `eTeleprompter/Features/Prompter/*` (add `DisplayLinkClock.swift`,
`PrompterControlsView.swift`, `PrompterSettingsSheet.swift`,
`MirrorContainer.swift`); **modifies** `App/eTeleprompterApp.swift` (`.commands`)
and `Features/Editor/EditorView.swift` only if the Start button needs polish.
**Depends on:** WP4 (engine/settings — hard), WP3 (entry point), WP2 (data to
read); starts when WP2–4 are merged.
**Scope:** full-screen reading view: text styled from ReadingSettings, engine-
driven offset, opens **paused at top**; mirror/flip/rotation on reading
container only, live during playback; control overlay (play/pause, stop,
slider 10–300 snapping to ints, −/+, numeric readout, gear → settings sheet,
X) auto-hides after 3 s during playback, tap (iPad)/mouse-move (Mac) reveals;
keyboard Space/↑/↓/Esc + macOS menu commands; 60 FPS on 10k words at 120 pt.
**Done when:** acceptance 6, 7, 8 pass on iPad Simulator and macOS.

**Dependency order:** WP1 → { WP2 ∥ WP3 ∥ WP4 } → WP5.

## 4. Build / run / test commands

```sh
# From repo root /Users/macs/Projects/eTeleprompter

# Build — iOS Simulator (acceptance 1)
xcodebuild -project eTeleprompter.xcodeproj -scheme eTeleprompter \
  -destination 'generic/platform=iOS Simulator' build CODE_SIGNING_ALLOWED=NO

# Build — macOS (acceptance 2)
xcodebuild -project eTeleprompter.xcodeproj -scheme eTeleprompter \
  -destination 'platform=macOS' build CODE_SIGNING_ALLOWED=NO

# Unit tests (engine/settings; macOS is fastest)
xcodebuild -project eTeleprompter.xcodeproj -scheme eTeleprompter \
  -destination 'platform=macOS' test CODE_SIGNING_ALLOWED=NO

# Run on an iPad simulator (pick a name from `xcrun simctl list devices available`)
xcodebuild -project eTeleprompter.xcodeproj -scheme eTeleprompter \
  -destination 'platform=iOS Simulator,name=iPad Pro 13-inch (M4)' build CODE_SIGNING_ALLOWED=NO
xcrun simctl boot "iPad Pro 13-inch (M4)" || true
open -a Simulator
xcrun simctl install booted \
  ~/Library/Developer/Xcode/DerivedData/eTeleprompter-*/Build/Products/Debug-iphonesimulator/eTeleprompter.app
xcrun simctl launch booted com.iprompter.iPrompter

# Launch the Mac app (built with ad-hoc identity "-", runs locally)
xcodebuild -project eTeleprompter.xcodeproj -scheme eTeleprompter \
  -destination 'platform=macOS' build   # note: signing allowed here so it launches
open ~/Library/Developer/Xcode/DerivedData/eTeleprompter-*/Build/Products/Debug/eTeleprompter.app
```

Rules of the road: never edit `eTeleprompter.xcodeproj` or `project.yml`
(synchronized folders make it unnecessary); stay inside your package's owned
files; both destination builds must pass before every merge to main.
